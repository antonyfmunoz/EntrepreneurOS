## 3. Design System — The Ethereal Professional

**File:** `.planning/design-system.md` (untracked — NOT committed yet)

**Creative north star:** The Lucid Architect — airy, illuminated, glassmorphic, no 1px borders.

**Core palette (locked):**
| Token | Hex |
|---|---|
| Primary | `#6a37d4` |
| Secondary | `#6448b2` |
| Primary-container / tertiary | `#ae8dff` |
| Surface | `#f5f6f7` |
| Background | `#ffffff` |
| On-surface | `#2c2f30` |

**Rules:**
- No 1px solid section borders — use background shifts
- Glassmorphism: `rgba(255,255,255,0.7)` + `backdrop-filter: blur(16px)`
- CTAs: `linear-gradient(135deg, #6a37d4, #ae8dff)`
- Border radius: 12px
- Font: Inter exclusively
- Icons: Material Symbols Outlined, monochrome `#2c2f30` (brand logos exempt); AI icon is `smart_toy`, never `rocket`
- Shadows: primary-tinted `rgba(106,55,212,0.08)`

**Enforcement chain:**
1. `build-stitch-prompt.ts` loads `.planning/design-system.md` verbatim + appends "MANDATORY COLOR VALUES" block with exact hex codes and a "NEVER USE" list (forbids brown `#914700`, off-palette blue/teal/orange)
2. `validate-design-system.ts` scans generated HTML for forbidden colors post-generation
3. Dual review (Claude + Gemini) scores visual consistency

## 4. This Session's Fixes

### 4.1 Component discovery via MCP cache-and-replay
**Problem:** `mcp__magicui__*` / `mcp__magic21__*` only exist inside the Claude Code harness. The headless `tsx` runner calls `discoverComponents(names)` with no `mcpInvoke` callback, so live MCP queries return nothing.

**Solution:**
- Queried real MCPs in-session (this conversation) for Button/Input/Card/Form/Label/Checkbox/Link + login inspiration
- Wrote results to `lib/ui-generator/component-cache.json` (13 entries: shadcn primitives, 21st.dev login patterns, MagicUI effects)
- Added `loadComponentCache()` + `matchCachedComponents()` to `component-discovery.ts`
- Preserved the existing `ComponentDiscoveryResult` contract — `formatDiscoveryForPrompt` and the runner are untouched
- When `mcpInvoke` is absent **and** live results came back empty, the function now falls through to a cache lookup

**Refresh policy:** re-run this cache-build prompt inside an interactive Claude Code session. Headless runs cannot regenerate the cache.

### 4.2 Preview UX
**Problem:** After Stitch generation, the only way to see output was navigating to Stitch manually.

**Solution (in `scripts/run-ui-gen-login.ts`):**
- Prints boxed clickable screenshot + HTML URLs per device after generation
- Starts a local `http.createServer` on `PORT=8765` (override via `PREVIEW_PORT`) serving `scripts/ui-gen-output/`
- Auto-opens `login-desktop.html` in the default browser — cross-platform (`start ""` / `open` / `xdg-open`), disable with `AUTO_OPEN=false`
- Waits for `SIGINT` (Ctrl+C) to continue to the approval gate

### 4.3 Fresh Stitch project
**Problem:** Old DESIGN.md / prior screens in the Stitch project polluted new generations.

**Solution:** Created a new project manually in stitch.withgoogle.com, pasted ID into `.env`. SDK has no `create_project` tool (verified by inspection of `lib/stitch/client.ts` + check-stitch-tools.ts). Automation is not worth it for a one-minute manual action.
