    **generateAnalyticsInjections(pageSpecs: Array<{ name: string; filePath: string; events: PageSpecFull["events"] }>): AnalyticsInjection[]** — For each page with events.length > 0:
    - `importCode`: `import { usePostHog } from "posthog-js/react";\nimport { useEffect } from "react";`
    - `hookCode`: `const posthog = usePostHog();`
    - `captureCode`: For each event:
      - If trigger is "load" or "page_view" or "mount": wrap in `useEffect(() => { posthog?.capture("${toSnakeCase(event.name)}"${propsObj}); }, []);`
      - If trigger is "click" or "submit" or other: generate a comment `// Analytics: call posthog?.capture("${toSnakeCase(event.name)}"${propsObj}) on ${event.trigger}` (manual placement — append model cannot reliably find button handlers)
      - `propsObj` = event.properties.length > 0 ? `, { ${event.properties.map(p => `${p}: undefined /* TODO: wire */`).join(", ")} }` : ""
    - Skip pages with 0 events entirely (return no injection)

    **buildProviderCode(): string** — Returns the PostHogProvider initialization code for App.tsx per Research Pattern 1 (Claude's discretion: App.tsx provider approach):
    ```typescript
    import posthog from "posthog-js";
    import { PostHogProvider } from "posthog-js/react";

    if (import.meta.env.VITE_POSTHOG_API_KEY) {
      posthog.init(import.meta.env.VITE_POSTHOG_API_KEY, {
        api_host: import.meta.env.VITE_POSTHOG_HOST ?? "https://app.posthog.com",
        capture_pageview: true,
        capture_pageleave: true,
      });
    }
    ```
    Plus JSX wrapper: `<PostHogProvider client={posthog}>{children}</PostHogProvider>`

    **buildIdentifyCode(authProvider: "firebase" | "passport" | null): string** — Per D-05:
    - If `"firebase"`: returns `useEffect(() => { if (user) { posthog.identify(user.id.toString(), { email: user.email, name: user.username }); } else { posthog.reset(); } }, [user]);`
    - If `"passport"`: same pattern but with `user.id` (numeric)
    - If `null`: returns `""` (empty — anonymous events only)
  </action>

    ```
    # PostHog Setup Guide

    1. Create a PostHog account at https://posthog.com (free tier available)
    2. Create a new project in PostHog
    3. Copy your **Project API Key** from Project Settings
    4. Add to your .env file:
       ```

    **generateDashboardGuide(taxonomyReport: TaxonomyReport): string** — Per D-16, returns a markdown guide for setting up the baseline PostHog dashboard. Includes instructions for creating these dashboard widgets in the PostHog UI:
    - **Page Views per Page** — Trends insight filtering by `$pageview` event, broken down by `$current_url`. Lists the specific page names from `taxonomyReport.allEvents` grouped by pageName.
    - **Event Counts** — Trends insight with each custom event from `taxonomyReport.allEvents` (unique event names). Shows how to add each as a separate series.
    - **Error Tracking** — Instructions to enable PostHog's error tracking (Session Replay > Enable exception autocapture), plus a Trends insight filtering `$exception` events.
    - **User Retention** — Retention insight using `$pageview` as both start and return event. Notes this requires `posthog.identify()` to be wired (only meaningful if auth is detected).
    This is a markdown document with PostHog UI instructions — not programmatic dashboard creation (PostHog dashboard API is undocumented/unstable).

    **createFeatureFlags(flags: string[], personalApiKey: string, projectId: string, fetchFn?: typeof fetch): Promise<{ flagsCreated: string[]; flagsFailed: string[] }>** — Per D-15:
    - Iterates flags array
    - For each flag, normalizes name with `toSnakeCase()`
    - POSTs to `https://app.posthog.com/api/projects/${projectId}/feature_flags/`
    - Headers: `Content-Type: application/json`, `Authorization: Bearer ${personalApiKey}`
    - Body: `{ key: snakeCaseName, name: originalName, active: false, filters: { groups: [{ rollout_percentage: 0 }] } }`
    - On success (res.ok): push to flagsCreated
    - On failure: console.warn and push to flagsFailed (NON-BLOCKING per Research anti-pattern guidance)
    - `fetchFn` parameter defaults to global `fetch` — allows test injection of mock fetch
