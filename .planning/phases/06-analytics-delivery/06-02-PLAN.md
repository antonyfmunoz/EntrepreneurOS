    **generateCIWorkflow(): string** — Returns YAML string for `.github/workflows/ci.yml` per D-12:
    ```yaml
    name: CI
    on:
      push:
        branches-ignore: [main]
      pull_request:

    jobs:
      ci:
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4
          - uses: actions/setup-node@v4
            with:
              node-version: "20"
              cache: "npm"
          - run: npm ci
          - run: npm run check
          - run: npm test
          - run: npm run build
    ```

    **generateCDWorkflow(target: HostingTarget): string** — Returns YAML string for `.github/workflows/cd.yml` per D-13/D-14. Two jobs: `deploy-staging` (environment: staging) and `deploy-production` (environment: production, needs: deploy-staging).

    Platform-specific deploy steps per target:
    - **railway**: Install `@railway/cli` via npm, run `railway up --service ${{ secrets.RAILWAY_SERVICE_NAME }}` with `RAILWAY_TOKEN` from secrets

    - **custom**: Add placeholder comment `# Add your custom deploy command here` with `docker build -t app .` and `docker push` as example

    Both jobs share common setup: checkout, setup-node@v4 with node 20 + npm cache, npm ci, npm run build. The deploy step differs per platform.

    All YAML is generated as template literals — no YAML library needed. Use consistent 2-space indentation.
