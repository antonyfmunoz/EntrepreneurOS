## Phase Boundary

Take approved Stitch HTML output from Phase 3 and integrate it as real, working React files in the existing EntrepreneurOS repo. This includes: brownfield auditing the existing codebase, translating Stitch HTML to shadcn/ui components, creating page files, wiring routes into App.tsx (Wouter), adding pages to sidebar navigation, wrapping in auth/company guards, and managing the git workflow (branch, commits, push, PR).

<decisions>
## Implementation Decisions

### Stitch-to-shadcn Translation
- **D-01:** Claude AI rewrite strategy. Send Stitch HTML + inventory of installed shadcn components to Claude. AI rewrites to use existing Button, Card, Dialog, etc. from client/src/components/ui/. No AST parsing step.
- **D-02:** Claude's Discretion on preservation balance. Claude determines per-page whether to keep Stitch layout structure with existing styling, or preserve Stitch fidelity. Adapt based on output quality.
- **D-03:** Auto-install missing shadcn components. When Stitch output needs a shadcn primitive that isn't installed (e.g., Tabs, Accordion), run `npx shadcn@latest add [component]` automatically. No user prompt needed.
- **D-04:** Static structure only — no data fetching in translated components. Phase 4 outputs pure presentational components with props. useQuery hooks and API wiring are Phase 5's concern.

### Page File Structure
- **D-05:** Claude's Discretion on granularity with heuristic: default to one page component per file in client/src/pages/ (matching existing pattern — dashboard.tsx, crm-page.tsx). Extract sub-components into client/src/components/ only when genuinely reused across multiple pages (e.g., a data table appearing on 3+ pages). Avoid unnecessary file explosion.
- **D-06:** Route paths come directly from PageSpec `route` field (already generated by Phase 2 spec parser). No re-derivation needed.

### Page Wiring
- **D-07:** All new pages wrapped in ProtectedRoute + CompanyGuard by default. Matches existing App.tsx pattern where every page except /auth uses ProtectedRoute.
- **D-08:** Default Layout wrapper with opt-out. New pages render inside existing Layout (sidebar + header + content area) by default. PageSpec flags like `fullScreen: true` or page types `onboarding`/`auth` trigger standalone rendering without the shell.
- **D-09:** Auto-add navigation entries. System reads page name from PageSpec, picks an appropriate remixicon icon (ri-* class, matching existing sidebar pattern), and adds entry to existing sidebar.tsx. Follows existing nav item pattern.

### Brownfield Conflict Resolution
- **D-10:** Flag conflicts + smart merge option. When a new page's route or filename collides with an existing one, system detects the conflict, shows both versions to the user, and offers three choices: replace existing, AI smart-merge, or skip. AI merge only runs when user explicitly picks it.
- **D-11:** Full brownfield audit scope. System inventories all existing pages, routes, shared components, hooks, and utilities before writing any file. Identifies reuse opportunities and potential conflicts.
- **D-12:** One-time audit with incremental updates. Full scan runs once before the first page integration. After each page, the inventory is updated incrementally (new files added to the index). No redundant full rescans.

### Git Workflow
- **D-13:** One feature branch per phase. Phase 4 creates a single integration branch (e.g., feature/ui-integration). All page integrations commit to it. One PR at the end.
- **D-14:** One atomic commit per page. Each page integration (translate + create file + wire route + add nav) is one commit. Clear history, easy to revert a single page.
- **D-15:** Auto-push after all pages, auto-create PR. Push to remote after all pages are integrated. Create a GitHub PR with a summary of all pages added. Matches GIT-03 requirement.
- **D-16:** Claude's Discretion on base branch. At execution time, analyze whether new pages depend on company-system infrastructure (CompanyGuard, use-company hook). If yes, branch from feature/company-system. If no dependency, branch from main.

### Claude's Discretion
- D-02: Preservation balance during translation (layout vs styling fidelity)
- D-05: Page file granularity (single file default, extract reused sub-components)
- D-16: Base branch selection based on dependency analysis

</decisions>

### Reusable Assets
- `client/src/components/ui/` -- Full shadcn/ui primitive library (Button, Card, Dialog, Input, etc.)
- `client/src/lib/protected-route.tsx` -- Auth wrapper, reuse directly for new pages
- `client/src/lib/company-guard.tsx` -- Company context guard, reuse directly

- `client/src/hooks/use-company.ts` -- Company context hook
- `lucide-react` -- Icon library already in use (existing nav items use Lucide icons)

### Established Patterns
- Wouter for routing (Switch/Route in App.tsx, not React Router)
- ProtectedRoute wraps all authenticated pages
- Pages are single-file components in client/src/pages/ with kebab-case filenames
- Layout component provides sidebar + header shell; pages render in content area
- TanStack Query for server state (Phase 5 will wire this)
- shadcn/ui for all UI primitives (Radix under the hood)
- Tailwind utility classes for styling
- 2-space indentation, no Prettier, TypeScript strict mode

### Integration Points
- `client/src/App.tsx` -- Add Route/ProtectedRoute entries for new pages
- `client/src/components/sidebar.tsx` -- Add navigation items for new pages
- `client/src/components/layout.tsx` -- Wraps page content (may need no changes)
- `package.json` -- If new shadcn components need installing
