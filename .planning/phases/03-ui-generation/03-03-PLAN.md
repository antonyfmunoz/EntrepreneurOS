       ```
       You are a UI quality reviewer for a SaaS application. Review the generated HTML against the page specification and design context provided.

       Score each dimension from 0.0 to 1.0 and provide specific findings (what passed, what failed, what's missing).

       Return a JSON object with exactly this shape:
       {

         },
         "contentQuality": {
           "score": 0.0-1.0,
           "findings": ["finding 1", "finding 2"]
         }
       }

       Scoring criteria per dimension:

       1. Spec Compliance (UIGEN-04):
          - All components from the spec are present in the HTML
          - Auth level is respected (login form for authenticated pages, no auth gate for public)
          - Empty state, loading state, and error state variants are present if specified
          - Data requirements are reflected in component structure

       2. Visual Consistency (UIGEN-05):
          - If design tokens provided: colors match token palette, typography matches font family and scale, spacing follows spacing unit, border radius matches
          - If no tokens (page 1): score based on internal consistency (one font family, coherent color palette, consistent spacing)

       3. Structural Completeness:
          - Navigation elements present (if not a standalone page like auth)
          - Responsive layout indicators (flex/grid, breakpoints)
          - Semantic HTML used (header, main, nav, section, not all divs)
          - Accessibility basics (form labels, alt text, ARIA where needed)

       4. Content Quality:
          - Reasonable placeholder text (not "Lorem ipsum" in visible areas)
          - Appropriate labels, headings, and button text
          - Icons or visual indicators where semantically appropriate
          - No debug text, TODO markers, or placeholder URLs visible

       Return valid JSON only — no markdown, no explanation.
       ```

    Create `.claude/skills/saas-dev/ui-generator/SKILL.md` as a Claude Code skill definition following the established pattern from the orchestrator skill.

    The skill must define the page-by-page UI generation pipeline that a Claude Code executor runs. Structure:

    **Skill Header:**
    ```markdown
    # Skill: saas-dev:ui-generator

    Generate pixel-quality UI for each page via Google Stitch API with design memory consistency and confidence-calibrated approval gates.

    ## Prerequisites
    - Phase 2 complete: SpecOutput with PageSpecFull[] available
    - STITCH_API_KEY configured in .env
    - AI_INTEGRATIONS_ANTHROPIC_API_KEY configured in .env
    - DATABASE_URL configured for Neon PostgreSQL
    ```

    **Inputs Section:**
    - `specOutput: SpecOutput` — from Phase 2 (pages array, suggestedOrder)
    - `projectConfig: ProjectConfig` — projectId, repoPath, framework, stitchProjectId
    - `deviceTypes: DeviceType[]` — user-configured, default `["DESKTOP"]` per D-03

    **Pipeline Steps:**

    Step 0 — Device Type Configuration (D-03):
    - Ask user: "Which device types should be generated? Options: DESKTOP (default), DESKTOP + MOBILE, DESKTOP + MOBILE + TABLET"
    - Default to DESKTOP only if user skips
    - Store as array for iteration

    Step 1 — Page Order:
    - Use `specOutput.suggestedOrder` if available
    - Otherwise process pages in priority order from PageSpecFull.priority
    - Log processing order to user

    Step 2 — For Each Page (loop):
    a. Build prompt: `buildStitchPrompt(pageSpec, currentTokens, priorScreenshotUrl)` from `lib/ui-generator/build-stitch-prompt.ts`
    b. For each deviceType in deviceTypes array:
       - Call `generateScreen(stitchProjectId, { prompt, deviceType })` from `lib/stitch/client.ts`
       - Fetch HTML: `const html = await fetch(result.htmlUrl).then(r => r.text())` — presigned URL, must fetch (Pitfall 1)
       - Store result: `{ htmlUrl, screenshotUrl, htmlContent, deviceType }`
    c. Self-review: `selfReview({ htmlContent: desktopHtml, screenshotUrls, spec: pageSpec, tokens: currentTokens, priorPatterns })` from `lib/ui-generator/self-review.ts`
       - Per D-12: when multiple device types, review desktop + mobile together in single call
    d. Approval gate: `evaluateApprovalGate(pageIndex, reviewScore)` from `lib/ui-generator/approval-gate.ts`

    Step 3 — Gate Handling:
    - If `needsUserApproval: true`:
      - Display `formatApprovalGateDisplay(...)` showing screenshots, scores, component checklist, action options
      - Wait for user response:
        - **Approve**: proceed to Step 4
        - **Reject + feedback**: append feedback to prompt, re-call Stitch (up to 3 retries per D-04), then re-review. Track retry count. After 3 rejections, escalate: "Maximum retries reached. Full history: [show all prompts and feedback]. Manual intervention needed."
        - **Skip**: mark page as `status: "skipped"` in pipelinePages, continue to next page
    - If `needsUserApproval: false`:
      - Display `formatAutoApproveNotice(pageName, pageIndex)` per D-16
      - Proceed to Step 4

    Step 4 — Post-Approval (on approve only):
    a. Extract tokens: `extractTokensFromHtml({ htmlContent, projectId, priorTokens: currentTokens })` from `lib/ui-generator/extract-tokens.ts`
    b. Detect conflicts: `detectPatternConflicts(existingPatterns, newPatterns)` from `lib/ui-generator/conflict-detector.ts`
    c. If conflicts detected (D-08):
       - Show conflicts to user with options: unify to existing, keep both as variants, override with new
       - Apply user's choice before persisting
    d. Persist tokens: INSERT new row into `dmTokens` table with incremented version (immutable revision model per D-07)
    e. Persist patterns: INSERT into `dmPatterns` table for each new/updated pattern
    f. Persist page record: INSERT into `dmPages` table with `approvedAt: new Date()`, `tokenVersionRef: newVersion`, `screenshotUrl`
    g. Update pipeline state: UPDATE `pipelinePages` row with `status: "complete"`, `output: JSON.stringify(UiGenPhaseOutput)`
    h. Update `currentTokens` and `existingPatterns` for next page iteration
    i. Update `priorScreenshotUrl` to this page's screenshot for next iteration

    Step 5 — Completion:
    - Log summary: pages approved, pages skipped, pages failed
    - Final token version number
    - Return `{ completedPages, skippedPages, tokenVersion, patternsExtracted }`

    **Error Handling:**
    - StitchWrapperError with `code: "ENV_MISSING"` — tell user to set STITCH_API_KEY
    - StitchWrapperError with `recoverable: false` — log error, mark page as failed, continue to next
    - Claude API errors — pRetry handles transients; after exhaustion, mark review as "review_failed" and escalate to user
    - Database write errors — log, do not block pipeline, warn user that design memory may be incomplete

    **Database Operations:**
    Document the exact Drizzle ORM insert patterns:
    ```typescript
    // Token persistence
    import { db } from "../../server/db.js";
    import { dmTokens, dmPatterns, dmPages, pipelinePages, insertDmTokenSchema } from "@shared/design-schema.js";
    import { eq, and } from "drizzle-orm";

    // Insert new token version
    const tokenRow = insertDmTokenSchema.parse({ projectId, version: nextVersion, ...mergedTokens });
    await db.insert(dmTokens).values(tokenRow);

    // Insert patterns
    for (const pattern of newPatterns) {
      await db.insert(dmPatterns).values({ projectId, ...pattern, pageSlugRef: pageSpec.route });
    }

    // Insert/update page record
    await db.insert(dmPages).values({ projectId, pageName, pageSlug: pageSpec.route, purpose: pageSpec.purpose, approvedAt: new Date(), tokenVersionRef: nextVersion, screenshotUrl });

    // Update pipeline page status
    await db.update(pipelinePages).set({ status: "complete", output: JSON.stringify(uiGenOutput), completedAt: new Date() }).where(and(eq(pipelinePages.runId, runId), eq(pipelinePages.pageIndex, pageIndex)));
    ```

    **Outputs:**
    - Per page: UiGenPhaseOutput (`{ htmlUrl, screenshotUrl, tokenVersion, approved }`)
    - Per run: `{ completedPages: number, skippedPages: number, failedPages: number, finalTokenVersion: number }`
