# Plan 03-08 — DESIGN.md Export/Import Workflow

## Objective

Snapshot the design system to a versioned `dm_design_md` table after Page 1 and reference it on every subsequent page, so design intent survives across the page loop even if individual extractions vary.

## Why

Stitch best practice is to export a DESIGN.md from the project after the first approved screen and feed it back into subsequent generations. The Stitch MCP does not currently expose `export_design_system` or `import_design_system` tools, but we can still get most of the benefit by:

1. Generating a Markdown snapshot from the most-recent dmTokens row after Page 1.
2. Storing it in a new `dm_design_md` table (immutable, versioned per project).
3. Referencing it from Page 2+ (currently via the existing token carry-forward; future Stitch MCP support will enable real import).

## What

1. **Schema**: Create `dm_design_md` table (migration 20260407): `id`, `project_id`, `version`, `content`, `exported_at` + index `(project_id, version DESC)`. Add `insertDmDesignMdSchema`.
2. **Library**: `lib/stitch/design-md.ts` exporting `exportDesignMD`, `generateDesignMDFromTokens`, `parseDesignMD`, `importDesignMD`, `DesignTokens`. `importDesignMD` is a no-op stub (reserved for real Stitch MCP).
3. **SKILL.md**: Insert Step 4a-1 (export after Page 1 token extraction) and Step 2a-5 (reference for Page 2+).
4. **Tests**: 7 vitest cases — round-trip generate→parse, null handling, no-op import.
