<objective>
Add pre-generation capabilities to the UI pipeline: (1) design system seeding from project spec/brand before any Stitch call, and (2) Gemini 2.0 Pro reference mockup generation before each Stitch call.

Purpose: Currently Page 1 goes to Stitch with zero design context (tokens are null). These enhancements seed the pipeline with an opinionated design system upfront (color palette, font pairing, spacing) and give Stitch a visual reference mockup to target, dramatically improving first-page quality and reducing rejection cycles.

Output: Two new modules (design-system-seeder.ts, gemini-mockup.ts), enhanced build-stitch-prompt.ts, updated types.ts, tests, and SKILL.md updates.
</objective>

    Implementation:
    - Check `process.env.GEMINI_API_KEY` — if missing, return null (non-blocking, mockup is enhancement not requirement)
    - Instantiate `new GoogleGenerativeAI(process.env.GEMINI_API_KEY)` and get model `gemini-2.0-flash-exp` (use flash for image generation, not pro — pro does not generate images)
    - Build a prompt: "Generate a UI mockup screenshot for a SaaS page with these characteristics: Name: {spec.name}, Purpose: {spec.purpose}, Components: {spec.components.join(', ')}. {token constraints if provided}. Generate a clean, modern UI design mockup as an image."
    - Call `model.generateContent({ contents: [{ role: "user", parts: [{ text: prompt }] }], generationConfig: { responseMimeType: "image/png" } })`
    - Extract the image from response inline data. If the response contains an image part (`part.inlineData`), return `{ imageBase64: part.inlineData.data, mimeType: part.inlineData.mimeType }`. Otherwise return null.
    - Wrap in try/catch — return null on any error (mockup generation is best-effort)
